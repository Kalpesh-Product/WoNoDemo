# Sales upload

Service references now use the exact IDs from WonoTestUserData.clientservices.csv: Co-working = 67d56b05ac5326fb7189d89e; Virtual Office = 67d56bacac5326fb7189d8b2. The importer requires these records to exist with the matching company and name and never creates or substitutes service records. clientservices.json is a reference file; its preflight insertion count is therefore zero. WorkationClient and MeetingClientRevenue have no service field in their schemas.

The source unit export defines total capacity, not vacant capacity. Preflight subtracts active existing clients from live unit capacities and fits new clients into the remaining desks. It prefers the intended unit, adjusts open/cabin mix as needed, then tries another referenced active unit if necessary. Client desk totals and corresponding credits stay consistent; existing clients and unit capacities are not changed. Preflight displays adjustments. If total capacity is insufficient, the import fails before any writes. Apply recalculates allocation inside the transaction.

Contains 104 meetingclientrevenues, 18 coworkingclients, 12 virtualofficeclients, 10 workationclients, and 2 clientservices. Names are professional fictional business names, amounts are USD, and activity dates are in April–September 2026. Contract and increment dates may extend into 2027. No extra coworking/virtual-office/workation revenue is generated by this bundle.

Company and unit/building references come from the supplied exports. WorkationClient currently only has clientName and startDate; its records have no company or unit field because the schema does not support them.

Meeting revenue links directly to each existing non-cancelled external meeting through the meeting ObjectId. Local files are previews. At import time, the importer reads live meetings, rooms, and visitors to calculate duration and use current room names, external client names, payment amounts, and paid/unpaid status. Revenue is skipped if an entry for the same company and meeting already exists. Meetings are not changed.

From server in Git Bash, with the target URI exported as DB_URL:

```bash
node scripts/importSalesUpload.js --db WonoDemoUserData
node scripts/importSalesUpload.js --db WonoDemoUserData --apply
```

The first command is read-only. It checks existing company, unit and building references, client email collisions, desk capacity, and external meeting references. It reuses the company's Co-working and Virtual Office service records by name, creating them only if missing. --apply writes to WonoDemoUserData on cluster0.d9cnr.mongodb.net in a transaction and preserves existing records. No account, company, unit, or building is created. No email is sent. Database verification has not been run locally.
